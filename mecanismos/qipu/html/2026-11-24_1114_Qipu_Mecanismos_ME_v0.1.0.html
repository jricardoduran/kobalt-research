01 · La posición también informa

Un bit tiene dos valores. Un registro de un bit dentro de una secuencia finita tiene, además, la posibilidad de no existir. La ausencia no es un tercer valor del bit: es una propiedad del dominio de la secuencia.

0

Existe el registro; rechazo.

1

Existe el registro; aceptación.

∅

La solicitud existe, pero la respuesta todavía no.

Si la solicitud tampoco existe, no hay estado de solicitud. Si la lectura falla o su integridad no es confiable, el estado es desconocido, no pendiente. La distinción es esencial para una implementación distribuida.

En Qipu las posiciones nacen del acto de registrar, no de una numeración anticipada. La estructura de la trayectoria permite derivar estados, cursores y correspondencias sin guardarlos como verdades independientes. Esta es una manifestación del principio de residuo mínimo.

02 · Una familia, no siete algoritmos

Sean w = 8b bits de ancho físico (b bytes), k bits de información y v = w − k bits de posición. Exigimos 1 ≤ k < w. Definimos D = 2ᵏ valores explícitos, M = D + 1 estados observables, P = 2ᵛ período posicional.

w = k + v; D = 2ᵏ; M = D + 1; P = 2ᵛ

La notación M-D no debe confundirse: M cuenta estados observables; D cuenta valores codificados. M3E1B es el alias histórico de M3E1 para un byte. En múltiples anchos, M3E1 por sí solo es ambiguo; proponemos identificar el perfil completo como ME(w,k) o M3E1-W16. Esta extensión de nomenclatura no cambia el formato anterior.

03 · Especificación binaria

Para una posición absoluta i ≥ 0 y un valor x con 0 ≤ x < D, el entero del registro es:

B(i,x) = P·x + (i mod P)
x = ⌊B/P⌋
m = B mod P
válido(i,B) ⇔ m = i mod P

La información ocupa los k bits más significativos, y el residuo los v menos significativos. Serializamos en big-endian, exactamente b bytes por registro. Posiciones desde cero. El cuerpo no incluye encabezado, relleno ni delimitadores; el perfil se conoce por contrato externo. Big-endian para múltiples bytes es una decisión de esta especificación experimental.

offset(i) = i·b
longitud válida L ⇔ L mod b = 0
n = L/b; último = n−1 (si n>0); siguiente = n

Ejemplo ME(8,1): i=16, x=1 → 128+16=144=0x90. ME(16,1): i=32768, x=1 → 32768=0x8000. El período no limita el tamaño de la trayectoria; la posición absoluta sigue siendo externa al residuo.

Para un perfil fijo y posición fija, la codificación es inyectiva en x y la decodificación la invierte exactamente: 0 ≤ i mod P < P. El máximo B es P(D−1)+(P−1)=PD−1=2ʷ−1, por lo que siempre cabe en w bits. No hay colisiones entre valores explícitos en un mismo slot.

05 · Espacio de estados y progreso emergente
Para N solicitudes existentes y n respuestas constituidas, con 0 ≤ n ≤ N, la respuesta de índice i existe exactamente cuando i < n. La autoridad solo puede resolver un prefijo, sin huecos. Los valores publicados son definitivos.
estado(i) = xᵢ, si 0 ≤ i < n
estado(i) = ∅, si n ≤ i < N
estado(i) = inexistente, si i ≥ N
pendientes = N−n; próxima solicitud = Q[n]
El número de configuraciones legítimas es Ω(N,D)=Σⱼ₌₀ᴺ Dʲ=(Dᴺ⁺¹−1)/(D−1), frente a (D+1)ᴺ cuando los estados son independientes. Para N=3 y D=2 hay 15 configuraciones en vez de 27. La estructura reduce el espacio permitido; no viola ningún límite de información.
Con 1 byte por respuesta, 1.000.000 de respuestas ocupan 1.000.000 bytes (~0,954 MiB), sin metadatos. Se sacrifica compactación frente a bit packing para obtener offsets directos, longitud inequívoca y redundancia posicional. Si se empaquetan bits, se requiere longitud lógica exacta y el último byte puede cambiar físicamente.


06 · Qué demuestra la redundancia posicional
En cada posición solo D de los 2ʷ posibles registros satisfacen la marca. Para una sustitución uniforme que incluye el original, la probabilidad de pasar es 1/P; condicionada a un cambio real, (D−1)/(2ʷ−1). Este modelo no es un modelo de atacante ni de error real de un medio específico.
AlteraciónResultado
Cambio en uno o más bits de posición, mismo slotDetectado siempre si cambia el residuo.
Cambio exclusivamente de bits de informaciónNo detectado.
Inserción/eliminación de d registros, con sufijo supervivienteDetectado por el desplazamiento si d mod P ≠ 0, sin otras alteraciones.
Intercambio de slots con residuos distintosDetectado.
Intercambio con igual residuo o ciclo completo eliminadoPuede pasar.
Truncamiento al final de registros completosNo detectado sin corte previo conocido.
Longitud no múltiplo del anchoDetectado; no interpretar como respuesta.
Reescritura deliberada, rollback, autenticidadNo garantizados.
Demostración del desplazamiento: el registro antes ubicado en j contiene j mod P. Tras moverse a j+d, el lector exige (j+d) mod P; ambos coinciden si y solo si P divide d. Esto explica la detección y su límite exacto. Verificar únicamente el último slot confirma una condición necesaria del final, no la integridad del prefijo.
La marca no es un hash, MAC ni firma. Complementar cuando sea necesario con autenticación de autoridad y compromisos verificables del corte/prefijo (K4B/K5B verifican sus marcos; un hash de un marco aislado no demuestra orden histórico). Una lectura válida puede estar desactualizada; preservar cortes previamente conocidos y distinguir desconocido de ausente.

08 · Constitución atómica por posición
El archivo es una secuencia append-only lógica. La marca no implementa atomicidad: la condición de longitud esperada y la escritura deben constituir una operación indivisible y durable en el adaptador.
append(i, bytes):
  si i = n y bytes válidos: extender atómicamente
  si i < n y bytes existentes iguales: éxito idempotente
  si i < n y difieren: conflicto, no sobrescribir
  si i > n: hueco, no escribir
Debe comprobarse el ancho y el residuo; no basta comparar el último byte. El adaptador impone un escritor lógico por archivo o serialización equivalente, lectura de cortes completos y ausencia de sobrescritura del prefijo. El laboratorio simula esto en memoria: no prueba una transacción en Drive. Actualizar un archivo conservando su ID no implica que Google Drive proporcione append condicional atómico. Las descargas por rango, CORS, permisos y caché requieren validación en el entorno real.


09 · Aplicación a la coherencia de trayectorias
La familia es autónoma. Una aplicación natural es el vector de respuestas de Qipu: cada nodo j escribe solicitudes Qⱼ append-only; la autoridad lee Qⱼ y escribe Rⱼ (ME(8,1)); también constituye una trayectoria canónica C. Los nodos leen Rⱼ y C por ubicaciones estables, independientemente y sin callbacks. N nodos necesitan 2N+1 archivos lógicos remotos, sin contar segmentos o derivados.
0 ≤ |Rⱼ| ≤ |Qⱼ| ≤ |Qⱼ local|
próxima solicitud de j = Qⱼ[|Rⱼ|]
Estas desigualdades describen cortes coherentes; lecturas de diferentes instantes pueden aparentar violaciones. Releer antes de concluir que hay corrupción. La autoridad resuelve en orden por nodo, puede intercalar nodos, y serializa los efectos canónicos. Aceptación: primero constituir el hecho canónico con origen recuperable (identidad estable del nodo/trayectoria, índice Q), luego registrar 1. Rechazo: registrar 0. Si se interrumpe entre ambas escrituras, recuperar el origen en C y completar el 1 sin duplicar la operación. No se requiere otro log si toda aceptación tiene evidencia canónica recuperable, incluso reconocimientos sin cambio comercial.
La trayectoria local conserva acciones, solicitudes y conocimiento adquirido, y no se reescribe. Los derivados operativos equivalen a recorrer el corte canónico conocido y aplicar solicitudes locales aún no incorporadas ni rechazadas, en orden y respetando contratos. Una aceptación recibida antes del hecho no elimina todavía el efecto provisional. Un hecho recibido antes de la respuesta elimina la duplicación mediante su origen. El rechazo no deshace una entrega física irreversible.
D_local = Aplicar(Derivar(C_h), efectos provisionales)
Convergencia = igualdad de derivados reconocidos a igual corte,
no igualdad de historias locales.
Lectura y escritura se separan: las ubicaciones estables y los rangos permiten descubrir la actualidad de un vector; la escritura pasa por el adaptador autorizado. FOLLOW toma el último slot, SPAN recorre todos, EMIT adquiere y verifica, TRAYECTORIA interpreta registros. Este documento no implementa ese lector remoto ni el mecanismo de autoridad; los delimita como aplicaciones posteriores.
